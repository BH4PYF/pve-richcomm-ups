# 续航模型标定

## 1. 为什么不用原厂电量

原厂"UPS Battery Level"是电压查表（见 [原厂电量表修正](06-原厂电量表修正.md)）：

```
charge% = round((V_block − 10.0) × 10) / 36 × 100
```

问题：

- 0.1 V/块一档，带载平台又极平，1% SOC 只对应约 0.05 V，查表分辨率不够。
- 不补偿负载压降：断电瞬间负载把电压拉低，原厂电量会从 97% 直接跳到 50%。
- 满量程被压在 20.0–27.2 V，顶端 7% 容量只占 0.6 V。

所以桥接自己维护 SOC，原厂值只做初值和对照（`battery.charge.vendor`）。

## 2. 公式

### 2.1 可用能量

`runtime.conf` 用三个参数隐式标定可用能量：

```
usable_wh = RUNTIME_MINUTES / 60 × REFERENCE_LOAD_PCT / 100 × RATED_WATTS
```

当前值：

```
50 / 60 × 0.22 × 400 = 73.3 Wh
```

> `RATED_WATTS` 在"标定"和"换算"两步里会被约掉：它既用来把参考负载换成瓦，又用来把实际负载换成瓦。改它不改变 SOC 与续航，只影响"多少瓦"的中间解释。保持 400 不动。

### 2.2 剩余时间

```
factor = REFERENCE_LOAD_PCT / max(load, MIN_LOAD_PCT)
seconds = RUNTIME_MINUTES × 60 × factor × SOC / 100
```

低压降额：

```
若 voltage < VOLTAGE_DERATE_START:
    k = (voltage − VOLTAGE_CUTOFF) / (VOLTAGE_DERATE_START − VOLTAGE_CUTOFF)
    seconds ×= clamp(k, 0.1, 1.0)
```

最后夹在 60 s–86400 s。`voltage` 是原厂 raw 整组电压（单块 ×2），不是显示值。

### 2.3 SOC 积分

- 市电：`soc += 100 / (CHARGE_HOURS × 3600) × dt`，上限 99%；只有电压 ≥ `FULL_VOLTAGE=26.7 V` 且 SOC ≥ 99.5% 才置 100%。
- 断电：`soc -= power_watts × dt / 3600 / usable_wh × 100`，`dt` 最多 120 s。
- 持久化在 `/var/lib/ups-pve/battery.json`，重启不丢。

## 3. 当前参数

| 参数 | 值 | 含义 |
|---|---|---|
| `RUNTIME_MINUTES` | 50 | 满电、22% 负载下的续航 |
| `REFERENCE_LOAD_PCT` | 22 | 标定参考负载 |
| `MIN_LOAD_PCT` | 5 | 负载下限，避免空载除零/虚高 |
| `RATED_WATTS` | 400 | 额定有功功率，仅用于瓦数换算 |
| `CHARGE_HOURS` | 10 | 市电下从当前 SOC 充到 99% 的时间 |
| `FULL_VOLTAGE` | 26.7 | 整组浮充判满电压（raw） |
| `VOLTAGE_OFFSET` | 0.80 | 仅显示校准，不参与计算 |
| `VOLTAGE_DERATE_START` | 22.6 | 开始线性降额的 raw 整组电压 |
| `VOLTAGE_CUTOFF` | 21.0 | 降额零点（推断的硬切断上限） |
| `LB_VOLTAGE` | 22.0 | 低电判定（raw），比 UPS 自身 21.8 V 蜂鸣提前 0.2 V |
| `LB_SOC` | 20 | 低电 SOC 判据 |

## 4. 标定过程

### 4.1 旧值（10-29）

```
RUNTIME_MINUTES=360
REFERENCE_LOAD_PCT=22
RATED_WATTS=400
→ usable_wh = 528 Wh
```

依据是标称 1080 Wh 打对折，属于"纸面估算"，没有实测支撑。`upsc battery.runtime` 在 18% 负载下给出 26136 s（7.26 小时）。

### 4.2 新值（10-30 09:27）

依据 01:22–02:25 的实测：

```
起点 24.60 V raw，终点 21.60 V
时长 63m53s = 63.88 min
负载 18% ≈ 72 W（按 400 W 额定）
输出能量 ≈ 72 × 63.88/60 × 1.065 ≈ 77 Wh
```

折算到参考负载 22%（88 W）：

```
77 Wh / 88 W × 60 ≈ 52.4 min
```

取 **50 min**，留 4% 余量：

```
usable_wh = 50/60 × 0.22 × 400 ≈ 73 Wh
```

同时把 `LB_VOLTAGE` 从 21.6 提到 22.0：实测 21.8 V 时 UPS 自己开始低电蜂鸣（状态位 `0x40`），NUT 的 LB 应该早 0.2 V，给 NAS 留关机时间。

### 4.3 验证

| 负载 | 公式 | `upsc battery.runtime` |
|---|---|---|
| 18% | 3000 × 22/18 × 0.99 = 3630 s | 3630 s |
| 22% | 3000 × 1 × 0.99 = 2970 s | 2970 s |

改前是 26136 s，改后 2970 s，量级与四次实测一致。

## 5. 这个数字的边界

- **它是"满电可用"的估计。** SOC 模型在市电下会按 10 小时充到 99%，但实测内置充电器是涓流，电池并没有真正充满。所以现在 `upsc` 显示的 2970 s 是"如果电池是满的"，不是"现在这块电池真实能撑 2970 s"。
- **73 Wh 是上限还是下限？** 01:22 那次放到 21.6 V，可能还没到硬切断（推断 20.0–21.0 V），所以 73 Wh 略偏保守；但那次起点也未必是真正的 100%，两者部分抵消。等外接充电器充满后复测才能定。
- **降额段没有实测。** `VOLTAGE_DERATE_START=22.6` 以下是按线性外推，没有放到 21.0 V 的数据。
- **PF/逆变效率未实测。** 72 W 是按额定 400 W × 负载百分比估的，实际有功功率可能有 ±15% 误差。要精确需要一台串在 UPS 输出端的功率计。
- **温度、老化未建模。** 冬天容量会再低一些。

## 6. 怎么改

改 `/etc/ups-pve/runtime.conf`，桥接每秒重读，约 10 秒生效，不用重启：

```bash
sudo editor /etc/ups-pve/runtime.conf
watch -n2 'upsc ups battery.runtime battery.charge ups.load'
```

注意：

- `RUNTIME_MINUTES` 是 22% 负载下的分钟数，不是任意负载。
- 改 `LB_VOLTAGE` 会同时影响 poller 的低电关机计时（poller 每秒读同一文件），两边保持一致。
- 改完建议 `systemctl restart ups-nut-bridge`，让 `ups.delay.shutdown` 等缓存值也刷新（续航本身不需要重启）。
- 改前备份：`cp runtime.conf /root/runtime.conf.bak.$(date +%s)`。

## 7. 复标定清单

1. 外接充电器把电池充到 27.6 V，静置 2 小时。
2. 装回 UPS，确认 `FULL_VOLTAGE` 能达到、SOC 到 100%。
3. 跑一次 60–120 分钟 `TL`，`ups-selftest-watch --min-pack 21.0 --max-runtime 9000`。
4. 记录：起点/终点电压、时长、平均负载、环境温度。
5. 用 `usable_wh = 平均功率 × 时长 / 3600 × 效率修正` 反算，和 73 Wh 比。
6. 若偏差 >20%，更新 `RUNTIME_MINUTES`，并在 `runtime.conf` 里补一段中文注释说明依据。
7. 把结果追加到 `logs/ups-test-history.log`。
